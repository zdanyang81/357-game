# 357 独立内测服务部署与回退边界

本部署仅用于已批准的微信内测，不是正式公开发布，不创建账号注册入口或公开房间列表。既有安卓、网页、其他HTTPS服务均不替换。新增监听为HTTPS 18086，内部权威服务仅监听127.0.0.1:18795。

## 部署构成

- 独立权威进程：系统动态用户，空capabilities；临时房间/头像仅存内存。最多100房间、每房间2席、空闲30分钟及硬上限4小时清理；重启会清除全部房间，不自动重放动作。
- 独立TLS进程：仅启动时以root读取既有spiet基础设施证书，创建TLS上下文后，在监听前清空补充组并降到UID/GID65534；降权失败拒绝监听。不复制证书私钥，不改既有证书权限，不借其他业务身份凭据。
- TLS代理只转固定loopback目标、允许的API路径和少数应用头，重写真实来源IP；后端只在显式信任本loopback代理时采用专用IP头，不能相信公网X-Forwarded-For。
- 两进程分别128MiB内存、25% CPU、32任务、256 FD，代码为root持有的只读不可变release；限制64连接。配置变更或新release只影响这两个357服务。

## 内测访问门禁

真实服务主入口要求本项目新生成的64位十六进制内测访问能力。没有或错误能力，健康检查外的所有API返回403；房间读取和走子还需该席位的独立随机token。

该能力只在本次微信预览构建中注入，经X-357-Access-Key请求头发送，不进入分享、URL、日志或源码仓库。它是可轮换的**构建cohort门禁**，不是微信身份、强用户认证或管理员权限。拿到房间码并持有本内测构建的人可占用空闲第二席；不得宣传为“只限某一微信好友身份”。不要将预览构建公开分发。

部署环境文件仅root可读。生成时只允许新建，不覆盖已有key。构建配置默认空：没有明确的HTTPS地址时，客户端显示“联网内测未开放”，离线玩法仍可用。注入后的构建包含cohort能力，需作为私有内测产物管理；公开源码包不包含此值。

```text
/opt/357-rooms/releases/<精确commit>/server/{http.js,rooms.js,tls-edge.js}
/opt/357-rooms/releases/<精确commit>/minigame/core/engine.js
/opt/357-rooms/current -> 已验证release
/etc/357-rooms/rooms.env                    root:root 0600
/etc/systemd/system/357-rooms.service
/etc/systemd/system/357-rooms-tls.service
```

先检查端口冲突、证书有效期及源文件SHA，再安装独立单元；systemd-analyze verify成功才可daemon-reload并启动这两个准确单元。不要重启或reload既有nginx、DSH或其他业务服务。查看状态时不要打印Environment、环境文件、请求头或原始含用户资料的HTTP正文。

## 验收

1. 正常信任链和主机名检查下本机TLS健康成功；实际backend为动态非root用户，TLS监听进程为UID65534、有效capabilities=0。
2. 合成两客户端经真实TLS入口建房、加入、按回合走完最后一颗判负、同一赢家、离开撤销；没有key时403，只有key而无席位token时401。用后清理合成房间，不输出任何真实key/token。
3. 从另一台已授权机器验证公网HTTPS可达。若云安全组或微信后台域名未配置，清楚记录，不开启其他无关端口或借旧业务入口绕过。
4. 微信正常模式必须具备HTTPS域名/端口、有效证书、小游戏账号能力和正确隐私声明。不关闭urlCheck或要求“打开调试”来冒充正常内测可用。
5. 两个真实微信账号/两手机验证好友卡片和房间码；头像选择、拒绝、相册转96像素PNG、对手展示与过期清除需真实验证。微信头像API存在不保证目标测试号返回非灰头像，失败回退默认头像。

## 停用与回退

只停止或禁用上述两个357单元即可关闭新增内测入口；不影响旧离线预览、默认分支或其他业务端口。回退release需先核对已有请求和房间状态，明确告知房间会丢失，再变更自身current链接并仅重启357单元。未知部署/发送结果先查询，不重投、不强行清锁。证书续期后需在受控窗口仅重启自身TLS进程以载入新证书，不改共享续期策略。

本文件是实施说明，不是部署、双手机验收或本人通过回执。实际结果需另存版本化证据。
